## 3. Векторная память (Vault RAG): Техническое состояние и оценка

- **Почему не использован GitHub PAT:**
  1. GitHub Models физически обращается к адресам `models.inference.ai.azure.com` (Azure AI), что прямо нарушало запрет на Azure.
  2. На персональных токенах GitHub действует лимит 15 запросов в минуту (RPM), что привело бы к ошибкам 429 при индексации базы.
- **Архитектура текущего решения:**
  - **Модель:** Google Gemini `gemini-embedding-2` с нативным параметром `outputDimensionality: 1536`.
  - **Схема БД:** Supabase `public.vault_embeddings` (`vector(1536)`). Никаких изменений схемы не потребовалось.
  - **Алгоритм поиска:** Гибридный RRF (*Reciprocal Rank Fusion*, $k=60$). Параллельно опрашивается семантический RPC `match_vault_chunks` и текстовый полнотекстовый поиск PostgreSQL (FTS). Сверху — локальный фоллбэк по `.md` файлам при отсутствии сети.
  - **Обработка квот:** Автоматическое определение заголовка `retry-after` с адаптивной паузой.
- **Текущая оценка:** **8.5 из 10**.
  - *Плюсы:* Мгновенная скорость (0.3 с), нулевая стоимость, 100% точность по E-кодам и терминам.
  - *Точка роста до 10/10:* Реиндексация старых 1 145 чанков в БД, которые ранее кодировались через OpenAI ada-002, чтобы привести 100% базы к единому векторному пространству Gemini.

## 4. Состояние ИИ-ассистента и B2B-стратегия

### Сценарий №1 («Собрать список покупок / Рецепты»): НА ПАУЗЕ
- Фронтенд готов (`AIRecipeWizardDock`, `AIRecipeRoleCarousel`, `AIRecipeSummaryBar`, 25 классических блюд Казахстана в `goldenRecipes.js`).
- Поставлен на паузу, так как базовый RPC `fn_search_store_products` перегружен триграммным поиском по всей 50-тысячной базе и упирается в таймауты.
- Возврат к сценарию запланирован после завершения фонового обогащения каталога 30 атрибутами и развертывания легковесного RPC `fn_find_recipe_products` (49 мс).

### B2B Экономика для владельцев супермаркетов (Подписка 15 000 – 45 000 ₸/мес)
Директорам не нужны «чат-боты», им нужны финансовые метрики:
1. **Спасение потерянных покупок (*Lost Sales*):** 2% покупателей сомневаются в составе (аллергии, лактоза, глютен, QMDB Halal) из-за мелкого шрифта 4pt и возвращают товар на полку. Körset AI за 1 с подтверждает безопасность -> +36 000 ₸ выручки в день (+1 080 000 ₸/мес на магазин).
2. **Рост среднего чека (*Basket Size*):** Сценарии «Собрать ужин» и «Перекус» превращают 1 пачку пельменей (1 500 ₸) в связку из 4 товаров (4 200 ₸).
3. **Разгрузка персонала зала (*Staff Workload*):** Снятие с мерчендайзеров 80% рутинных вопросов (*«Где дрожжи?», «Это халал?»*).
4. **Аналитика скрытого спроса (*Zero-Search Analytics*):** Отчеты о товарах, которые искали покупатели, но которых не было на полке (1С этого не видит).

### Спецификация 4 сценариев:
- **Сценарий 1:** Рецептурная корзина (на паузе).
- **Сценарий 2:** «Где товар на полке» (навигация по отделам и рядам).
- **Сценарий 3:** «Разбор состава и добавок» (светофор безопасности: польза / сомнения / халал и E-коды).
- **Сценарий 4:** «Подбор по бюджету / Перекус» (готовые бандлы до 1000 ₸, 2000 ₸, 3500 ₸).
