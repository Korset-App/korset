# Поздний ответ сканирования и выбранная точка

П11 общего плана требует, чтобы старый ответ не возвращал покупателя в предыдущую точку. Ручной поиск уже отбрасывает результат после пересоздания экрана: адресная проверка подтвердила сохранение новой точки, пустую панель недавних сканов и последующий успешный ручной поиск товара второй точки. Гипотеза ошибки ручного пути не подтвердилась; его код не менялся.

Автоматический обработчик после ожидания переходил без повторной проверки актуальности. Два браузерных воспроизведения вернули покупателя из `/s/pilot-b/scan` и `/s/pilot-a/catalog` к карточке первой точки. Лог `../scanner-store-scope-camera-red-20261014.log`; первоначальные неудачи настройки теста не считаются доказательством дефекта приложения.

В `ScanScreen.jsx` результат после ожидания проверяет срок жизни экрана и номер запуска сканера. Адрес использует сохранённую исходную точку. Та же проверка усилена после ожидания сравнения. Фоновый результат после штатного быстрого перехода записывает недавний скан только пока текущий адрес относится к исходной точке; завершённое сканирование внутри неё сохраняется. Остановка камеры не изменяет этот номер сама по себе, поэтому обычный успех не отбрасывается.

## Проверки

- Совместный прогон согласия/ручного поиска с двумя новыми автоматическими случаями и ручным поздним ответом: 26/26, `../scanner-store-scope-green-20261014.log`.
- Дополнительный финальный набор автоматической ветки: 4/4, `../scanner-store-scope-extra-final-20261014.log`: смена точки до ответа, уход в каталог до ответа, успешная карточка/недавний скан без ухода, фоновый ответ после штатного перехода и последующей смены точки. Успешная карточка проверена по названию; источниковый маршрут загружает сохранённую тестовую позицию. После добавления этих двух случаев приложение не менялось.
- Существующий связанный модульный набор: 37/37, `../scanner-store-scope-unit-20261014.log`.
- `check:agent:ui`, адресный ESLint и проверка различий прошли; `../scanner-store-scope-ui-20261014.log`.
- Независимый разбор изменённых строк не нашёл конкретной блокирующей регрессии; проверяющий тесты не запускал.

Видеопоток подменён canvas; оптическое распознавание не заявляется проверенным. Вызван действующий обработчик двух последовательных результатов декодирования, поиск использует настоящую цепочку приложения с отложенными подменёнными ответами. Штрихкод скопирован из прежней `UNKNOWN_EAN`, данные позиции/цена соответствуют существующей записи Pilot A. Физическая камера, рабочая база, внешние сервисы, публикация и участок Antigravity не затронуты.

Следующий самостоятельный участок — П08/П09: адресная проверка сочетаний неизвестного состава, молочного белка/безлактозности и пищевых предпочтений по существующим правилам и тестам. Не делать общий аудит или инвентаризацию; сначала определить конкретный отсутствующий сценарий и получить доказательства поведения. Пилот реального магазина по-прежнему требует упаковок, устройства и разрешённой выгрузки UMAG.
