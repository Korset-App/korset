# Обзор спроса: отказ, отсутствие показателя и настоящий ноль

## Подтверждённые случаи П14

Общий отказ сканов, пустой обзор и сохранение периода уже имели проверки. Отдельно воспроизведён отказ только числа покупателей: значение становилось прочерком, но не было ни объяснения, ни возможности повторить этот запрос; другие показатели и подсказки продолжали работать. Журнал до исправления: `dashboard-customer-metric-red-20261014.log` рядом с рабочей копией.

Два дополнительных воспроизведения показали различие между успешным сетевым ответом и подтверждённым числом: null вместо результата числа покупателей и ответ подсчёта сканов без точного количества объявлялись нулями. Последний случай создавал ложный вывод об отсутствии сканов. Журнал: `dashboard-missing-metric-red-20261014.log`.

Сохранённое локальное определение миграции 076 использует COUNT для покупателей и явный ноль для пустого покрытия; денежная условная оценка использует COALESCE и положительные цены. Это основание для обработки отсутствующего числа как нарушения контракта; текущая рабочая база и её фактическая версия не проверялись. Миграции не менялись.

## Изменение

У отдельного сбоя числа покупателей есть безопасное локализованное объяснение и повтор его запроса. Пока запрос выполняется, повтор не запускает ещё один запрос. Другие выводы не подавляются: этот показатель не является входом их существующего расчёта. Повтор с ответом 48 или настоящим нулём восстанавливает соответствующее значение и убирает ошибку. Ошибка оформлена внутри ячейки и помещается на ширине 320.

Чтение пяти числовых показателей проверяет наличие и корректность значения: сканы, число активных товаров, число покупателей, условная денежная оценка и покрытие. Ноль и числовые строки принимаются; денежные/процентные дроби сохраняются. Счётчики должны быть точными неотрицательными целыми, процент находится в диапазоне 0–100. Null, пустая строка, неверный тип, бесконечность и невозможные значения вызывают существующее состояние ошибки вместо выдуманного нуля. Единственный найденный потребитель этих пяти функций — `useRetailOverview`.

Расчёт условной оценки спроса, SQL, права, область точки, период запросов и рабочая база не менялись. Политика проверки таблиц/других списков не расширялась. Это адресная поправка достоверности числовых показателей, не общий пересмотр методики аналитики.
