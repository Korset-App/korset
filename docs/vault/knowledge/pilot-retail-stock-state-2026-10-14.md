# Неизвестное наличие в кабинете

Сверены актуальные границы: Antigravity проверяет витрину/настройки основной папки; каталог не входит в его ночной участок. Исходные разделённые компоненты из прежнего статического отчёта отсутствуют в изолированной версии, поэтому вывод проверен по её собственному `RetailProductsScreen.jsx`, без переноса внешней реализации.

Браузер подтвердил включённый переключатель (`aria-checked=true`) для `unknown`: `../retail-stock-red-20261014.log`. Старое следующее состояние для unknown/null было `out_of_stock`. Теперь только `in_stock`/`low_stock` означают включённый контроль; неизвестность явно подписана существующим переводом «Наличие требует уточнения». Подтверждение неизвестности записывает `in_stock`; переходы из известных состояний сохранены. Внешний вид карточек и их общие правила прозрачности не менялись.

Контроль стал обычной кнопкой с ролью переключателя и доступным именем: действует клавиатура, позиции учётной системы и ожидающая запись заблокированы. Отказ показывает безопасное сообщение RU/KZ именно для изменяемого товара; исходный статус возвращается прежним механизмом восстановления. Сообщение сервера не выводится.

Проверка задержки выявила зависшую блокировку после уже полученного ответа PATCH: `../retail-stock-pending-20261014.log`. Сравнение свойств запомненной карточки игнорировало изменения операции. Оно теперь учитывает ожидание, отказ и идентификатор товара операции; разблокировка после ответа подтверждена. Это исправление состояния карточки, не ослабление защиты записи.

## Проверки

- `tests/retail/stockState.spec.js`: 15/15 основного финального прогона, `../retail-stock-final-20261014.log`. Восемь сочетаний 390/1440, RU/KZ, обе темы; точные статус, идентификаторы товара/магазина в PATCH; отказ/восстановление и безопасная ошибка; задержка без второго запроса и разблокировка; запрет учётного изменения; null и известные in/low/out.
- Редактор сетки: отдельно 2/2, подтверждение с клавиатуры на KZ/dark/390 и отказ с восстановлением. `../retail-stock-grid-20261014.log`.
- `check:agent:ui` прошёл, `../retail-stock-ui-20261014.log`. После последних дополнений тестов адресный ESLint прошёл без ошибок; унаследованные предупреждения экрана вне изменяемого контроля сохранены. Проверка различий прошла.
- Изображения `unknown-stock-390-ru-light.png` и `unknown-stock-1440-kz-dark.png` просмотрены в `scratch/retail-visibility-2026-10-14/test-results/stockState-*`. Это проверка подписи/контроля, не полная визуальная приёмка каталога.
- Независимый ограниченный разбор конкретной регрессии не выявил, тесты проверяющий не запускал.

Все сетевые ответы подменены, владелец тестовый. Запись наблюдалась только в обработчике подмены; рабочая база не читалась/не менялась. Используется прежний тестовый UNKNOWN_EAN, не новый реальный штрихкод. Защита учётных данных, витрина/настройки, основная папка и публикация не затронуты.

Следующий самостоятельный участок — буквальный поиск каталога. В текущем `Highlight` поисковая строка напрямую вставляется в `RegExp`; сначала воспроизвести ввод скобки/плюса в интерфейсе, не считать кодовую гипотезу готовым дефектом. Старый вывод внешнего отчёта о клиентских фильтрах автоматически не переносить: эта изолированная версия уже использует серверный поиск. Реальные данные UMAG и магазин остаются непроверенными.
