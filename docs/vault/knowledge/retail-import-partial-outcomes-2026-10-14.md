# Частичная запись импорта: фактический результат и неопределённость

Изолированная ветка `codex/pilot-readiness-2026-10-11`, основа `01496b4`. Рабочая база, схема, права доступа и внешний клиент не изменены. Истинность реальных выгрузок UMAG не подтверждается этими тестами.

До исправления ошибка массового обновления запускала до 20 параллельных отдельных записей независимо от причины отказа. Потеря ответа поздней стадии могла прервать формирование отчёта после уже подтверждённых изменений. Это не давало надёжного разделения отказа и неизвестного результата.

Теперь подтверждённые количества `updated`, `staged`, `autoResolved` сохраняются. Явные отказы находятся в `failed`; потерянный ответ, ошибка связи/HTTP 5xx, повреждённый либо частичный ответ — в `unconfirmed` с этапом `known`, `staging` или `resolution`. HTTP-код берётся из ответа клиента Supabase, где он действительно находится, а не только из объекта ошибки. Для нулевого подтверждённого количества все соответствующие строки явно не записаны. При положительном частичном счётчике известна сумма, но не личности строк: список кандидатов неопределённости может пересекаться с подтверждённым количеством и не суммируется с ним.

Отдельные записи допускаются только при установленном отсутствии массовой функции (`PGRST202`/`42883`), последовательно. Ошибка прав либо неопределённый результат не запускают автоматический повтор; отдельная операция после отсутствующей функции не является переигрыванием возможно завершённого массового запроса. Последовательный запасной путь продолжает обработку остальных строк; общий процесс записи один. Частичная выгрузка не удаляет отсутствующие строки и не меняет их наличие.

После подтверждённой или возможной записи магазинных полей экран запрашивает обновление каталога для исходной точки. Отказ последующего чтения не меняет подтверждённый счётчик записи: общий контекст сохраняет прежние данные с признаком ошибки каталога. Транспортный сбой сопоставления не отменяет подтверждённую постановку в очередь; её итог и неопределённость сопоставления показаны отдельно на RU/KZ. Автоматического повтора нет; перед ручной повторной загрузкой управляющий должен сверить актуальные данные. Повторные записи разных устройств и долговременный журнал импорта этим пакетом не реализованы.

Проверки: 21/21 адресный модульный набор выполнения; общий набор 963/963; 28/28 браузерных сценариев импорта и контекста. Переводы, проверка кода и сборка успешны. Браузерные ответы подменены, рабочие записи отсутствуют. Новые сценарии проходят RU/светлую и KZ/тёмную темы, прежние сценарии покрывают обе темы обоих языков. Четыре браузерных сценария до исправления воспроизвели отсутствие безопасного отчёта. Независимый разбор изменений блокирующих регрессий не обнаружил.

Журналы вне рабочей копии: `scratch/pilot-readiness-2026-10-11/overnight-import-{browser-red,browser,unit,ui}.log`. Предыдущие правила файла и ограничения: `docs/vault/knowledge/retail-import-pilot-guards-2026-10-11.md`.

Внешний каталог кабинета отдельно просмотрен только по коду: `scratch/overnight-retail-review-2026-10-14/report.md`. Он ещё не принят и не перенесён. Пилот требует разрешённого файла магазина, проверки на физическом устройстве и решения о выпуске; локальные результаты этого не заменяют.
