# Раздельный кеш разработки изолированной копии

Изолированная копия использует ссылку `node_modules` (каталог установленных зависимостей) на `C:/projects/korset/node_modules`. Пакеты React и React DOM в обеих папках имеют одинаковые реальные пути. Прежде оба Vite-сервера также записывали промежуточные оптимизированные зависимости в один физический каталог `C:/projects/korset/node_modules/.vite`.

Это нарушение изоляции подтверждено вызовом `resolveConfig` (получение фактической конфигурации установленного Vite) для обеих папок и проверкой реальных путей файловой системы. Проверка отказала до исправления, поскольку физические каталоги кеша совпали. Не запускались дополнительные серверы основной папки и не завершались чужие процессы.

В `vite.config.js` нашей копии задан `cacheDir` (путь промежуточных файлов) относительно расположения самой конфигурации: `scratch/vite-cache`. Теперь её реальный кеш находится внутри `scratch/pilot-readiness-2026-10-11/worktree/scratch/vite-cache`; основная папка продолжает использовать прежний каталог. Обе папки сохраняют один установленный набор пакетов, но наша копия больше не пишет оптимизированные зависимости в кеш внешнего сервера. Кеши не удалялись; исходная папка и участок Antigravity не редактировались.

После исправления та же проверка проходит и подтверждает разные физические пути и нахождение нового кеша внутри рабочей копии. Покупательские сценарии, весовые позиции и контекст магазина проходят: 21/21 браузерный тест. Переводы, проверка кода и сборка успешны. Ответы API (программного интерфейса) подменены; рабочая база не использовалась.

Артефакты рядом с рабочей копией: `dev-cache-isolation-red-20261014.log`, `dev-cache-isolation-green-20261014.log`, `isolated-cache-browser-20261014.log`, `isolated-cache-ui-20261014.log`. Проверка: `scratch/dev-cache-isolation-2026-10-14/verify.mjs`.

Наличие общего кеша не доказывает, что именно он вызвал четыре внешние ошибки React на `/s/audit`. Внешний сценарий после этого центральным агентом не запускался. Корректность основной версии не объявляется установленной. Следующий независимый сценарий — вход покупателя на главную магазина по ссылке, используемой QR: прежние центральные браузерные проверки открывали каталог напрямую, а внешний сбой зарегистрирован на главной.
