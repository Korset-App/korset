# Мастер-план доведения Körset до готовности к пилоту (Сентябрь 2026)

## 1. Подтверждённая продуктовая концепция (Digital Storefront)
- **Основной продукт:** Цифровой сайт-витрина для офлайн-магазина (например, `korset.kz/s/mars`).
- **Сценарий из дома (2GIS / Google Maps / шеринг):** Покупатель переходит по ссылке из карты или мессенджера, попадает на стильный сайт конкретного магазина с актуальными ценами, составом, поиском и списком покупок.
- **Сценарий у полки в зале:** Тот же сайт даёт возможность мгновенно открыть сканер штрихкодов камерой смартфона для проверки состава (Fit-Check: аллергены, халал, диабет/диеты).
- **Ценность для ритейлера:** Магазин получает «свой сайт под ключ» с товарами и ценами без разработки за миллионы, привлекает клиентов из локального поиска 2GIS и сокращает отток покупателей из-за сомнений по составу.

## 2. Ключевые фокусы разработки на неделю

### Блок 1. Исправление критических багов и раздражителей
- **Баг «Кэш устарел» (`OfflineBanner.jsx`):**
  - *Проблема:* Баннер с предупреждением об устаревшем кэше висит поверх экрана даже тогда, когда пользователь находится онлайн и просматривает актуальный каталог с сервера.
  - *Решение:* Показывать предупреждение об оффлайн-кэше ТОЛЬКО в оффлайн-режиме (`!isOnline`). При подключении к сети фоном обновлять локальный кэш без навязчивого желтого баннера.
- **Баги светлой темы:**
  - `ProfileScreen.jsx`: устранить эффект «белое на белом», добавить чёткие карточные границы, контрастные разделители и мягкие тени.
  - Retail Cabinet (`RetailDashboardScreen`, `RetailSettingsScreen`): стабилизировать сетку, цвета шрифтов и карточек в светлой теме.

### Блок 2. Редизайн и визуальное доведение экранов
- **Главный экран (`HomeScreen.jsx` / `HomeScreen.css`) — [День 1 завершён]:**

## 3. Архитектура эффективной работы без сжигания токенов
- **AGENTS.md:** держится ультра-компактным (< 1.5 KB), только незыблемые правила.
- **docs/CONTEXT.md:** актуальная карта системы, обновляется только при изменении структуры.
- **On-Demand Skills:** инструкции для агентов вызываются семантически через `.agent/skills/`.
- **Subagents:** рутинный поиск файлов и кода выполняется в изолированном контексте через дешёвую модель `flash`.
