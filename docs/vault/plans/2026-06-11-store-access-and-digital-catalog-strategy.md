# Стратегия: Цифровой каталог магазина + пересмотр доступа

> Статус: решения приняты, ожидает implementation plan.
> После реализации — обновить CONTEXT.md.

---

## Суть стратегического поворота

**Было:** Körset = умный ассистент для покупателя внутри магазина. Доступ ограничен.

**Стало:** Körset = цифровая витрина магазина (публичный каталог с ценами) + умный ассистент поверх него.

**B2B pitch (аргумент для продаж) стал сильнее:**
- Было: «Покупатели смогут проверять аллергены у вас в магазине»
- Стало: «У вашего магазина появится онлайн-каталог. Люди смотрят из дома, приходят к вам»

**Аналоги:** Dukaan (Индия), QR-меню для ресторанов, 2GIS с каталогом.
**Конкуренты в КЗ:** отсутствуют. Ниша пустая. AinurPOS/SYNTERRA — только B2B-инструменты без потребительского слоя.
**Уникальность Körset:** цифровой каталог + Fit-Check (халал, аллергены, диеты). Нигде в мире такой комбинации для минимаркетов нет.

## Принятые решения

### 1. Модель доступа — всё открыто

| Функция | Доступ |
|---|---|
| Каталог, цены, категории, поиск | ✅ Открыт для всех без регистрации |
| Карточка товара (фото, состав, цена) | ✅ Открыт для всех |
| Fit-Check | ✅ Без регистрации (профиль хранится в localStorage) |
| AI-ассистент | ✅ Без регистрации |
| Список покупок | ✅ Без регистрации (хранится локально) |
| История сканирований | ✅ Без регистрации (хранится локально) |
| Синхронизация между устройствами | 🔒 Только с аккаунтом — естественный апгрейд |

**Аккаунт = апгрейд, не стена.** Предлагается в контексте (когда польза очевидна), не принудительно при входе.

Пример: «Хотите чтобы список покупок сохранился на всех устройствах?»

**Access gate, токены, коды на баннере — отменены.** Не строим.

### 2. Статус наличия — не показываем покупателям

- Товар есть в каталоге → он есть
- Товар помечен `out_of_stock` в Retail Cabinet → скрываем из публичного каталога
- Никаких бейджей «в наличии / нет в наличии» для покупателя

### 3. Избранное → Список покупок

Технически то же самое (`user_favorites` / localStorage), но другое позиционирование:
- «Список покупок» = планирую купить
- Сценарий: просмотр каталога дома → добавление в список → поход в магазин → отметка купленного
- Это связующее звено между «дома» и «в магазине»

### 4. QR-код на баннере — просто быстрый вход

QR ведёт на `korset.kz/s/mars` — никаких токенов, никаких кодов.
На баннере: QR-код + текстовый URL (korset.kz/mars) — на случай если QR не сканируется.
Никаких 4-значных кодов, никаких электронных табло.

### 5. Сканер — остаётся, меняет роль

- Дома: не нужен
- В магазине: «взял товар → отсканировал → мгновенная карточка с Fit-Check» — быстрее чем искать в каталоге

Сканер = дополнение к каталогу для использования у полки. CTA «Сканировать» убирается с HomeScreen как главный элемент.

### 6. HomeScreen — владелец дорабатывает сам

Концепция: убрать большую кнопку «Сканировать» как главный CTA.
Добавить быстрые действия: Каталог / Сканировать / Список покупок / История.
Правильная иерархия для нового сценария использования.

## Критические риски (нерешённые)

### 🔴 Риск 1: Актуальность цен

**Проблема:** если цена в каталоге не соответствует реальной — покупатель чувствует себя обманутым.
**Зависит от:** как легко владельцу обновлять цены.

**Вопрос к проверке:** есть ли в Retail Cabinet массовое обновление цен (CSV/XLS импорт)?
- Если нет → это нужно добавить до запуска публичного каталога.
- Редактирование по одному товару при 500+ позициях → владелец физически не будет этого делать.

### 🔴 Риск 2: Покрытие global_products базы

**Проблема:** для онбординга магазин сканирует штрих-коды → система должна найти товар автоматически (название, фото, состав). Если база покрывает < 70% товаров → онбординг становится болью.

**Вопрос к проверке:** какой процент типичных казахстанских минимаркет-товаров есть в global_products?

### 🟡 Риск 3: Режим черновика

**Проблема:** новый магазин подключился, но ещё не заполнил каталог. Публично показывать пустой каталог нельзя.

**Решение:** статус магазина `draft` vs `published`. Только `published` магазины видны публично.
Кнопка «Опубликовать каталог» в Retail Cabinet после заполнения.

## SEO-план (приоритеты)

### Бесплатно — для пилота

1. **Meta-теги** (title, description, Open Graph) для каждой страницы магазина и товара
   - `<title>Марс Минимаркет — каталог товаров, цены | Körset</title>`
   - Время: ~3 часа работы

2. **Schema.org структурированная разметка** — ключевой пропущенный момент
   - Для магазина: `LocalBusiness` с адресом, часами, категорией
   - Для товаров: `Product` с ценой, валютой, описанием
   - Результат: Google может показывать товары с ценами прямо в поиске (Rich Results)
   - Время: ~4 часа работы, огромный эффект без изменений архитектуры

3. **Sitemap.xml + Google Search Console**
   - Список всех страниц магазинов и товаров
   - Время: ~2 часа

4. **Open Graph для шеринга** (WhatsApp/Telegram превью ссылок)
   - Когда человек делится ссылкой на товар → красивое превью с фото и ценой
   - Ключевой вирусный механизм

5. **2GIS** — в КЗ часто важнее Google Maps
   - Каждый магазин-клиент добавляет ссылку на каталог в свой 2GIS профиль
   - Делается вручную, бесплатно, прямо сейчас

6. **Google Business Profile**
   - Каждый магазин добавляет `korset.kz/s/mars` как сайт
   - Появляется в Google Maps и локальном поиске

### После пилота — при масштабировании

- SSR / пре-рендеринг для лучшей индексации каталога
- Google Ads для кампании «Körset — каталоги магазинов»

### Реалистичные ожидания поиска

| Запрос | Шанс с meta+Schema+GBP |
|---|---|
| «Mars» | ❌ Слишком общее |
| «Марс магазин» | 🟡 20–40% |
| «Марс минимаркет Астана» | ✅ 60–80% |
| «Марс Нурсат минимаркет» (точное название) | ✅ 80–90% |
| Название товара + магазин | ✅ Через Schema.org Rich Results |

## Вирусный механизм роста

Shareable links (делиться ссылками) — незаметный механизм роста:

```
Мама в WhatsApp: «Смотри, в Марсе гречка 890₸ — дёшево!»
[ссылка с превью: фото товара + цена + логотип Körset]
Дочка кликает → попадает на страницу товара → видит Körset → «Что это?»
```

Требует: хорошие Open Graph теги + быстрая загрузка карточки товара.

## Онбординг нового магазина (процесс)

1. Встреча → договор → создание аккаунта в Retail Cabinet
2. Владелец или Körset-менеджер сканирует штрих-коды товаров (система автоматически подтягивает global_products)
3. Проставление цен (в идеале — через CSV импорт)
4. Добавление данных магазина (адрес, часы, логотип, фото)
5. Статус `draft` → проверка качества каталога
6. «Опубликовать каталог» → статус `published`
7. Печать баннера с QR (Körset предоставляет шаблон из /qr-print)
8. Установка баннера в магазине
9. Добавление ссылки в 2GIS и Google Business Profile магазина

- ❌ Сложная аналитическая система
- ❌ Статус наличия для покупателей

## Что делаем в пилоте (implementation scope)

1. **Не строим access gate** — это экономия времени, а не новая работа
2. **Список покупок** — переименование избранного (i18n + иконка) ~1 час
3. **Скрытие out_of_stock товаров** из публичного каталога ~30 мин
4. **Meta-теги** для страниц магазинов и товаров ~3 часа
5. **Schema.org разметка** для магазинов и товаров ~4 часа
6. **Open Graph шеринг** для карточек товаров ~2 часа
7. **Sitemap.xml** ~2 часа
8. **Режим черновика** `draft/published` для магазинов ~3 часа
9. **CSV импорт цен** (если нет) — критически для актуальности ~6-8 часов
10. **Проверка global_products покрытия** — аудит данных

## Ценность для магазина — финальная формулировка

Что магазин получает за подписку:
- Публичный URL каталога (korset.kz/s/mars) + QR-код
- Retail Cabinet: управление товарами, ценами, статусом
- Аналитика: просмотры каталога, популярные товары, поисковые запросы
- Fit-Check для покупателей по их профилю (аллергены, халал, диеты)
- AI-ассистент на основе их каталога
- SEO-оптимизированная страница магазина в Google / 2GIS
- Инструмент для Instagram/WhatsApp: «Наш каталог: ссылка»

**Ни один конкурент в КЗ не даёт потребительский слой поверх инструментов для владельца.**
