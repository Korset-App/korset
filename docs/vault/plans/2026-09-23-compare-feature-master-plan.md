## 1. Цель и критерии успеха

**Продуктовая цель:** покупатель у полки за 3–5 секунд понимает, какой из двух товаров
лучше подходит **ему** (аллергии, халал, диеты) и почему. Сценарий должен помогать
продавать подписку магазину (B2B2C).

**Критерии успеха:**

1. Не падает ни при одном разумном входе (сравнение с собой, неизвестный EAN, нет КБЖУ,
   разные категории, товар не в наличии).
2. Вердикт понятен без объяснений: что выбрать / почему / насколько уверен.
3. Ключевые пути покрыты **поведенческими** тестами (e2e), не проверками текста исходника.
4. RU и KZ равноценны; тёмная и светлая темы не ломаются.
5. Стоимость AI на один показ сравнения предсказуема.
6. Сценарий измеряется (магазин видит, что сравнивают).

## 6. Рекомендация по AI-объяснению (вопрос B)

**Рекомендую: AI строго по кнопке «Объяснить выбор», с кэшем и честной деградацией.**

Почему:

1. **Вердикт у нас уже детерминированный и сильный** — 16 тестов, взвешенный скоринг,
   безопасность (аллергены) имеет вес 45. Экрану не нужен LLM, чтобы ответить «что выбрать».
2. **Авто-запрос = неконтролируемый расход.** Один показ = один вызов. В магазине с живым
   трафиком это деньги за объяснения, которые большинство не читает.
3. **Анонимный лимит 8/мин.** Без JWT запрос идёт под анонимным лимитом; при 429 текст
   просто исчезает (`setAiText(null)`), пользователь видит пустоту вместо объяснения.
4. **Главное правило продукта:** нельзя выдавать AI-догадку как проверенный факт. Когда
   объяснение приходит само, оно воспринимается как часть вердикта. Когда его просят
   кнопкой — как дополнение.

Что это даёт на практике:

- на открытии экрана **0 запросов** (проверяется перехватом в e2e);
- по клику — 1 запрос, с `Authorization`, если сессия есть (лимит 30/мин вместо 8);
- повторное объяснение той же пары — из кэша (ключ: пара EAN + язык + хеш профиля),
  0 запросов;
- при 429/квоте/ошибке — видимый честный текст («Сейчас не могу объяснить — вердикт выше
  актуален»), а не пустое место;
- кнопка визуально второстепенна: звезда экрана — детерминированный вердикт.

Если хочешь сохранить «вау» для авторизованных: можно автоматически показывать объяснение
только для залогиненных (лимит 30/мин) и по кнопке — для гостей. Скажи — заложу это вместо
варианта по умолчанию.

## 7. Аналитика сравнений: проект схемы (нужно твоё «добро»)

Минимальная таблица + запись из клиента + метрика в дашборде магазина:

```sql
create table if not exists public.compare_events (
  id uuid primary key default uuid_generate_v4(),
  store_id uuid references public.stores(id) on delete cascade,
  user_id uuid null,
  ean_a text not null,
  ean_b text not null,
  status text null,          -- winner | draw | blocked | same_product | not_found
  winner_side text null,     -- A | B | null
  primary_reason text null,  -- safety | halal | price | nutrition | ...
  lang text null,
  created_at timestamptz not null default now()
);

create index if not exists idx_compare_events_store_created
  on public.compare_events (store_id, created_at desc);

alter table public.compare_events enable row level security;
-- INSERT: anon + authenticated, только активный магазин; SELECT: владелец/админ.
```

Метрика в Retail Dashboard: «Сравнений за период» + топ-пар. Ничего не создаю до явного
подтверждения схемы — по правилам проекта миграции и RLS согласовываются отдельно.
