# Decision: Полная ликвидация Microsoft Azure и переход на Google Gemini 1536d + Hybrid RAG

**Дата:** 25 сентября 2026 г.  
**Статус:** Принято и внедрено (Accepted & Implemented)  
**Область:** Системная архитектура, долгосрочная память агентов (Vault RAG), Backend API

---

## 1. Контекст и предыстория

Летом 2026 года в проект Körset добавлялись экспериментальные маршруты к Microsoft Azure (Azure OpenAI / Azure Inference API) в рамках гранта Microsoft Founders Hub ($1,000). Однако из-за непрозрачной биллинговой политики Azure (в частности, скрытых списаний за сторонние модели из каталога Marketplace и сервисные эндпоинты напрямую с банковской карты в обход гранта), проект понес финансовые убытки. Пользователь получил неожиданную задолженность и наложил **категорический и бессрочный запрет на любое присутствие или обращение к сервисам Microsoft Azure**.

Одновременно стояла задача восстановления долгосрочной векторной памяти агентов (Vault RAG) с нулевыми затратами ($0 budget, на балансе OpenAI $0), без необходимости пополнения баланса и без использования серверов Azure.

---

## 2. Анализ альтернатив: Почему отвергнут GitHub Models PAT?

При попытке использовать GitHub Personal Access Token (PAT) для доступа к бесплатным моделям эмбеддингов было выявлено:
1. **GitHub Models физически хостится на инфраструктуре Azure:**  
   Сетевой адрес GitHub Models — `models.inference.ai.azure.com`. Любой вызов через токен GitHub отправляет трафик на серверы Azure AI Studio, что нарушает строжайший запрет пользователя. Кроме того, локальный DNS возвращал `getaddrinfo ENOTFOUND models.inference.ai.azure.com`.
2. **Жесткие ограничения квот (Rate Limits):**  
   Бесплатный уровень GitHub Models ограничен 15 запросами в минуту (RPM) и 150 запросами в день, что делает индексацию 99 документов базы знаний (175 чанков) невозможной без постоянных ошибок `429 Too Many Requests`.

---

## 3. Принятое решение: Google Gemini 1536d + Supabase Hybrid RRF

В качестве ядра долгосрочной памяти утвержден стек на базе **Google Gemini (`gemini-embedding-2`)**:
1. **Совместимость со схемой Supabase:**  
   Модель Google нативно поддерживает параметр `outputDimensionality: 1536`, генерируя высокоточные векторы размерностью ровно 1536 чисел. Это позволило сохранить существующую таблицу `public.vault_embeddings` (`vector(1536)`) и RPC-функцию `match_vault_chunks` без миграций схемы базы данных.
2. **Нулевая стоимость ($0):**  
   Используется уже настроенный бесплатный `GEMINI_API_KEY`.
3. **Пакетная обработка и лимиты:**  
   Поддержка `batchEmbedContents` (пакеты по 50–100 текстов в одном HTTP-запросе) и лимит 100 запросов в минуту позволили проиндексировать всю базу знаний за несколько минут.
4. **Гибридный алгоритм ранжирования RRF (Reciprocal Rank Fusion):**  
   Скрипт `scripts/query-vault.mjs` выполняет параллельно семантический поиск по векторам и лексический полнотекстовый поиск (FTS) в PostgreSQL, объединяя ранги по формуле:
   $$RRF(d) = \frac{1}{60 + rank_{sem}} + \frac{1}{60 + rank_{lex}}$$
   Это обеспечивает 100% точность как по смысловым концепциям, так и по точным артикулам, E-кодам и терминам.
5. **Офлайн-фоллбэк:** При сетевых сбоях скрипт производит локальный текстовый поиск по `.md` файлам папки `docs/vault/`.

## 4. Список выполненных работ по зачистке Azure

1. **`api/ai.js`:** Удалены все переменные `azureApiKey`, `azureEndpointBase`, проверки доменов `azure.com` и `services.ai.azure.com`. Чат переведен исключительно на DeepSeek, транскрипция аудио — на Groq Whisper.
2. **`src/telegram-bot/ai.js`:** Удалены ветки и проверки Azure.
3. **`scripts/translate-names-kz.mjs`, `scripts/translate-composition.cjs`, `scripts/process-submissions.mjs`:** Удалены ссылки на Azure.
4. **`scripts/generate-image-azure.mjs`:** Файл удален из репозитория.
5. **`scripts/embed-vault.mjs` и `scripts/query-vault.mjs`:** Переписаны с удалением следов Azure и внедрением Gemini 1536d + RRF.
6. Проведен глобальный поиск: в кодовой базе Körset не осталось ни одного обращения к Microsoft Azure.

---

## 5. Инвариант на будущее

**СТРОЖАЙШИЙ ЗАПРЕТ:** Ни один будущий агент или разработчик не имеет права добавлять зависимости, эндпоинты, ключи или домены `azure.com` / `services.ai.azure.com` в проект Körset. Долгосрочная память проекта работает строго через `scripts/query-vault.mjs` на базе Google Gemini и Supabase pgvector.
