# Как работать над Körset без лишнего расхода

## Выбор модели

| Задача в проекте | Модель | Уровень рассуждений |
| --- | --- | --- |
| Найти компонент, поправить текст RU/KZ, отступы, простую ошибку в известном файле | Luna | Низкий |
| Каталог, профиль, кабинет магазина, компоненты React, обычные ошибки и тесты | Sol | Средний |
| Сложные ошибки состояния магазина, работы без сети, сравнения товаров | Sol; Astra при неразрешённой сложности | Средний; высокий для Astra |
| Авторизация, политики доступа к строкам, миграции, точность штрихкодов и архитектура импорта | Astra | Высокий |
| Проверка важного изменения перед выпуском | Astra с конкретными изменениями и результатами тестов | Высокий |

Это практическое распределение, а не обещание одинакового качества или определённого
процента экономии. Низкий уровень рассуждений Astra не делает её дешёвой Luna.
Максимальный уровень нужен только при доказанной сложности, не для обычных экранов.

## Что настроено

- `.codex/config.toml`: Sol/средний, Luna/низкий для помощников, максимум два помощника,
  ограниченный вывод инструментов. Значения подтверждены локальным API Codex.
- Через официальный локальный API отключены 52 лишних или дублирующих навыка
  в пользовательских настройках Codex; каталог подтвердил `enabled: false`.
  Файлы сохранены. Резервная копия: `~/.codex/config.toml.before-workflow-skills`.
  Уже открытая задача может сохранять прежний каталог; для нового состава открыть новую.
- Важные навыки сохранены: отладка, тесты, проверка результата, React, дизайн,
  Supabase, браузерные проверки и основные операции Vercel.
- Плагины GitHub, Supabase и Vercel установлены согласно каталогу подключений.
  Проверены живыми запросами: репозиторий GitHub Korset-App/korset, проект Supabase Korset и проект Vercel
  korset. Ошибка прав Vercel устранена переподключением к команде владельца.
- OpenCode: сохранены поставщик и модель, включена очистка устаревших результатов
  инструментов при сжатии контекста, убраны неподтверждённые параметры.
- `.agent/skills/korset-workflow` — общий вход для других редакторов.
  Инструкции модели не заменяют её выбор в интерфейсе Antigravity/OpenCode.

Новая задача подхватит настройки Codex; уже открытая может сохранять выбранную модель.
После перезапуска проверьте в переключателе **Sol / Medium (средний)**.
Установленные версии плагинов могут менять пути навыков: после обновления проверить
список доступных навыков; конфигурация содержит пути к текущей версии Vercel.

## Хороший запрос

«Исправь [конкретное поведение] на [экране]. Ожидаю [результат]. Сохрани текущий
дизайн и правила магазина. Проверь затронутый сценарий. Другие части не меняй».

Одна задача — один результат. Не начинать каждый раз с полного аудита проекта.
При передаче другой модели дать: цель, изменённые файлы, принятые решения,
результат проверок и оставшийся вопрос. Не копировать весь разговор.
Использовать новую задачу после завершённого этапа, а не каждый мелкий шаг.
Для параллельной работы нужны разные файлы или отдельные рабочие копии.
Текущие незавершённые изменения разделены в `docs/WORKING_CHANGES.md`.
Перед помощником назначить владельца, точные файлы и критерий готовности; главный
агент проверяет итог и запускает общий набор проверок один раз. Не использовать
`git add .` или `git add -A` при смешанных изменениях разных задач.

## Jev — только внутренний помощник

Команда: `node scripts/jev-workflow.mjs --input scratch/jev-input.json`.
По умолчанию только локальная проверка запроса. `--execute` отправляет его TypeSafe
и может расходовать баланс; перед первым запуском согласовать передачу и расход.
Ключ читается из переменной окружения или `.env.local`, в продукт не попадает.

Пример файла:

```json
{
  "state": "Document A describes CSS tokens. Document B describes database migrations.",
  "questions": {
    "ui_reference": {
      "type": "choice",
      "instructions": "Which document is relevant to changing button colors?",
      "criteria": {"a": "Document A", "b": "Document B", "neither": "Neither"}
    }
  }
}
```

Использовать для пакета независимых оценок релевантности или классификации, если
это действительно заменяет много чтения Sol/Astra. Для Luna и простых решений
не вызывать. Не передавать секреты, данные покупателей, весь репозиторий.
Ответ Jev — рекомендация: он не разрешает действия, не отменяет тесты и не проверяет
безопасность. Низкая уверенность требует обычной проверки агентом.
Подключение проверено одним искусственным примером: правильный выбор, уверенность
0,98, 336 входных и 40 выходных токенов TypeSafe. Общая экономия Astra не измерена:
один успешный вызов не является сравнением одинаковых задач с Jev и без него.

## Как оценивать расход без выдуманных процентов

Для обычной задачи достаточно модели, числа помощников, результата и проверок в
краткой передаче работы. Не запускать отдельного агента для подсчёта экономии.
Если нужен эксперимент: зафиксировать остаток лимита в интерфейсе Codex до и после,
не запускать другие задачи на аккаунте в этот промежуток. Это расход аккаунта,
а не точный счёт токенов конкретной модели. Вызовы Jev возвращают собственный `usage`
(расход); сохранить вывод локально в `scratch/`, не смешивать его с лимитом Codex.
Сравнивать одинаковый объём работы и качество результата, а не длину ответа.

## Проверки

`npm run check:agent:docs` — документы и память;
`node --test tests/unit/jevWorkflow.test.mjs` — внутренний Jev без сети;
`npm run test:unit` — логика; `npm run check:agent:ui` — интерфейс;
`npm run check:agent:full` — общий выпуск. Проверять изменённое поведение,
не повторять полный набор без новых изменений.

Полный набор включает сборку и браузерный тест переходов и перезагрузки без сети.
В автоматической проверке GitHub устанавливается Chromium; локально используется
Chrome. `PWA_BROWSER_CHANNEL=chromium` переключает на установленный Chromium.
`npm run lint` сохраняет видимость 82 существовавших предупреждений, но блокирует
новые по каждой паре файл/правило и любые ошибки. Базу `scripts/lint-baseline.json`
нельзя увеличивать ради прохождения проверки; при исправлении предупреждений уменьшать.
